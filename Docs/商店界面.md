# 商店界面

从 Bootstrap 开局，进入休整区并靠近商店柜台，用当前交互键打开。Esc 或鼠标右键关闭；打开时世界暂停。

## 布局与操作

- 上方四件商品：点击看详情，右侧“购买”按钮完成交易。价格只显示数字，骨髓不足时变红并禁用购买。
- 下方背包：固定十四格，只显示未装备器官；没有分页和容量数字。点击后右侧操作变为“出售”。无拖动、装配、卸下或返回按钮。
- 右侧详情：图标、名称、类型、可滚动说明、交易价格和大尺寸操作按钮。缺图时显示器官名称。
- 顶部余额：`Assets/Art/Items/marrow.png` 图标与当前数值。
- 刷新按钮显示下一次刷新费用，余额不足时禁用。首次费用及递增规则沿用 RunController。

购买后商品显示“已售出”，保持商品选中，新物品追加到背包。背包满时购买按钮显示“背包已满”并禁用，不扣钱、不消耗商品；出售后恢复购买。出售后清空选择，避免连续点击误卖下一件。同波重开不刷新商品。售出价格沿用配置基础价格的一半，向下取整。

背包已满时，击杀掉落与波次器官奖励直接按同一出售价格结算骨髓，不受骨髓获取倍率影响，不额外提示，也不生成器官入包动画。满包不影响进入下一波。已装备器官不占背包格；满包不能卸下，但可以与背包器官等量替换。

## 编辑入口

`Assets/Resources/Menus/Shop.prefab` 为独立商店预制体，界面位置与尺寸均可在编辑器调整。`FlowShopWindow` 负责展示与选择状态，交易仍调用 RunController，不直接修改货币或库存。

`Tools > SpringUp > Flow > Build Shop UI` 显式重建商店默认布局，会覆盖该预制体的手动排版。背景使用 `Assets/Art/UI/Store.png` 的 `Store_0`，以 1586×992 设计尺寸对齐原图中的四件商品、刷新按钮、十四格背包和右侧详情；图片上的标题和格框不重复绘制。刷新费用放在原图刷新按钮右侧，交易按钮位于详情区底部。

`SpringUp.EditorChecks.ShopUiBuilder.BuildFixedInventoryUi` 同时重建商店并仅删除现有实验室 Prefab 的分页对象，保留其余手动布局。

## 轻量验收

`SpringUp.EditorChecks.ShopUiChecks.RunBatch` 检查购买、售卖、重复点击、重开售出状态、付费刷新、满包按钮及余额不足；输出 1440×900、1280×720 的截图到 `Logs/ShopUI`。`RewardEconomyTests` 覆盖容量边界、满包交易与奖励自动出售。不需要执行整套游戏流程测试。
