# 器官反馈与配置检查

更新：2026-10-16。

## 试玩入口

打开 `Assets/Scenes/SpringUpDemo.unity`。左上角当前装备中的普通槽位，在实际发动攻击或触发器条件成立时闪亮 0.35 秒；躯干属于持续属性，不显示出手闪光。装备仍只能在休息期间修改。

点击装备标题右侧“伤害 / 触发记录”，展开或收起面板。面板显示本波伤害前六名和最近四次发动记录，相同短链编号表示属于同一条触发链。触发保护拦截也会记录。槽位闪光表示成功发动，不代表已经命中敌人；没有有效目标导致无法出手时不会闪亮。

统计按器官定义合并，同种器官装多件合计。统计的是敌人实际损失生命，包含弹体、激光、范围伤害及流血等持续伤害；不把过量伤害、未命中、黑洞吸引算成伤害。躯干增伤归入造成伤害的执行器。每波开始重置，停止战斗不会提前清除统计。

## 程序接口

`SpringUpRunDriver.CombatReport` 暴露报告；`BattleOrganCombat.Report` 在结算直接伤害与状态伤害时上报实际扣血。

- `History`：最近 64 条发动/触发保护记录，包含来源实例、完整链编号和链深度；不保存敌人或可变上下文引用。
- `Damage`：按定义 ID 汇总实际伤害，最多 128 项（含溢出合并项）。
- `IsFlashing(part, slot)`：槽位是否处于提示时间内。
- `ResetWave()`：开始新波次时清空；`Bind(null)`：解除管道订阅。
- `Revision`：供界面判断记录是否变化，收起面板时不构建统计文字。

当前是战斗入口的轻量记录面板，不是完整历史回放或整局排行榜；实验室仍使用已有预览事件日志。它不实现前级器官修改后级攻击参数的 Event → Event 机制。

## 配置检查

Unity 菜单 `Tools → SpringUp → 检查 → 器官配置完整性` 扫描器官配置、调用各行为已有的参数校验、检查重复 ID 和默认目录引用。错误在 Console 汇总并带资源路径；合法但未加入默认目录的器官给出警告。

同一个 OrganConfig 不能同时关联执行器、触发器、躯干中的多种配置，运行时也会拒绝这种歧义，避免原先按优先级静默忽略配置。

检查不要求 D 的全部旧设计已实现，也不自动修改掉落和经济表。

## 验证范围

新增自动化覆盖一万次出手记录的容量边界、重复绑定、实际伤害累积、一千个来源溢出汇总、解绑、每波清空、歧义配置拒绝，以及实战伤害接入和面板展开收起。

混合效果压力检查同时启动 384 个效果并推进到自然结束，再检查 256 个毒雾取消后的清理；使用模拟世界，不代表真实显卡帧率或最终性能验收。既有执行器、触发器、躯干与整局流程回归继续保留。

自动化结果见 `Logs/organ-report-checks-final.log` 与 `Logs/organ-report-visual.log`。验证使用隔离副本 `Logs/EquipmentHudValidation` 与本机缓存依赖（URP 17.5.0；项目声明为 17.6.0）；正式资源、Packages 和用户场景不因测试而重写。完整生存试玩、正式美术以及目标硬件的帧率仍需后续验收。
