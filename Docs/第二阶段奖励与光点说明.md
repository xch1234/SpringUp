# 第二阶段：额外保底、击杀器官与奖励光点（2026-10-18）

本记录替代第一阶段中“没有波末骨髓”“0.3 秒驻留方块”“清场删除奖励表现”等规则。敌人基础定义、前六波刷怪截止时间和第七波刷怪/结束规则沿用第一阶段。

## 奖励与配置

`Assets/Data/Waves/waves.json` 是本阶段经济调参入口：

- `marrow_reward`：前六波固定额外发放 50、60、70、80、90、100；不是补足余额。第七波为 0，代码也只对前六波发放保底。
- `kill_organ_chance`：每次真实死亡独立判定，初始为 `0.005`（0.5%）；不受骨髓倍率影响，没有连续失败补偿。
- `random_drop_pool`：该波唯一有效奖励池。过滤不存在、未接入当前战斗定义和重复池条目；空池/缺少池安全跳过。可再次抽中已持有器官，每次产生独立库存实例。第七波池仍为空，没有补充内容。
- 前六波波末恰好抽取一个器官，替换旧数量。`guaranteed_drops`、`optional_drops` 和 `random_drop_count` 仅兼容旧数据，不再额外发奖或改变“一件”的规则。
- 所有金额通过同一套 decimal 小数余量累计和装备倍率结算，不使用随机浮动。器官与骨髓都在死亡提交时完成，随后表现层只读取结果。

以上金额和概率均为可配置调试初值，未经平衡试玩验证。

死亡出生 ID 同时保护骨髓、器官及概率抽样不被重复触发。木桩、训练目标、清场、退出、回池不结算；兵工厂产出的 Normal 不区分来源。波末先进入 Settling，重复调用无法发奖。击杀入库不发送 LoadoutChanged、不自动装备，因此不重建管道、不重置攻击节奏。旧 Demo 使用共享结算；没有 Bootstrap 接收点时跳过动画。

## 光点与 UI 接收点

停止 Play，在 Inspector 打开 `Assets/Data/Rewards/RewardFlightSettings.asset`：

| 参数 | 初值 / 用途 |
|---|---|
| Sprite | 空时程序生成同一种小闪光点；可换 Sprite |
| Marrow Color / Organ Color | 金色 / 紫色 |
| Size | 14 个 Canvas 单位 |
| Hold Seconds | 0.1 秒 |
| Flight Seconds | 0.4 秒 |
| Arrival Seconds | 0.08 秒缩小消失 |
| Arc Height | 35 个 Canvas 单位，轻微弧线 |
| Flight Progress | 默认平方加速曲线，先慢后快；Inspector 可改曲线 |
| Receiver Anchor | `(0.03, 0.96)`，左上角归一化锚点 |
| Max Concurrent | 128；超限只省略表现，不减少奖励 |

Bootstrap 的 FlowApplication 持有该配置引用，场景生成器也接同一资源。运行时接收点位于 `Global UI/Windows/Reward flights/Reward receiver`，为 RectTransform；可在 Play 中观察锚点，持久调参修改配置中的 Receiver Anchor。

光点从死亡位置转换成 UI 起点后只保存归一化坐标，不持有敌人或战斗相机。屏幕外起点夹到可视边缘，CanvasScaler/窗口尺寸变化时重新按当前 RectTransform 计算轨迹。骨髓每个敌人一个点，有器官奖励再加一个异色点，无名称、金额文字或拾取碰撞。表现没有随机经济调用，也没有到达发奖回调。

表现管理器属于持续加载的 Bootstrap Canvas，使用对象复用和并发限制。Battle → Rest 和普通清场不清理动画、不等待它结束；使用 unscaledDeltaTime，但尊重 PauseService 的显式暂停原因。切场景专用租约只暂停战场，不暂停光点。放弃、本局返回主菜单、新开局会统一 Clear，旧光点不会进入新局。第一阶段 MarrowDeathVisual 和清场调用已删除。

## 无限库存与暂缓的 UI

`Inventory.UnequippedCapacity()` 返回 `null` 明确表示无限，兼容方法 `UnequippedWithinCap()` 恒为 true；没有任意大容量常量。购买与下一波入口、商店按钮都移除了容量阻挡，卸下和奖励入库无容量限制。身体槽位、部位合法性、战斗只读/休整装卸权限不变。

本次不重做库存 UI：旧界面可能仍显示“数量/空白上限”、旧超限说明，已有卡片数量/布局可能无法完整显示大量库存，出售列表的排版和滚动仍需后续统一处理。容量相关器官文案/展示也需要随 UI 整理；旧容量修正已不参与库存限制。这些纯显示问题不再用容量判断禁用购买或阻止下一波。

## 验证与人工验收
