更新：2026-10-17。对应本次六项要求。日常查参数可以先读本页；逐个查 `.cs` 的职责、入口和修改位置，见 [程序 A 脚本逐项说明与器官对照](程序A脚本逐项说明与器官对照.md)。

## 1. Hand 已经怎样整理

器官资源现在按用途分类，共 **19 种执行器、10 种触发器、7 种躯干，仍是 36 种定义**。普通器官可以装在头、手、腿；资源放在哪个文件夹不限制装备部位。仅休息期允许改装。

原 `Assets/Data/Organs/Hand/` 中六种执行器已移入 `Assets/Data/Organs/Actuators/`，并统一为入口配置与行为配置：

- 拳头：`Fist.asset → FistBehaviour.asset`。
- 钢管：`SteelPipe.asset → SteelPipeBehaviour.asset`，默认关联眩晕状态。
- 锈刀：`RustKnife.asset → RustKnifeBehaviour.asset`，默认关联流血状态。
- 粘液腺：`SlimeGland.asset → SlimeGlandBehaviour.asset`，默认关联减速状态。
- 坍缩体：`CollapseBody.asset → CollapseBodyBehaviour.asset`，生成有寿命的黑洞。
- TNT：`TNT.asset → TNTBehaviour.asset`，直接范围爆炸。

六份 `*Behaviour.asset` 共用 [DirectActuatorConfig.cs](../Assets/Scripts/Organs/DirectActuatorConfig.cs)，与原有执行器一样继承 `OrganActuatorConfig`。不需要再各写一个 `Fist.cs`、`SteelPipe.cs`。

旧入口资源的 GUID、器官 ID、默认效果参数保持不变，目录、场景、库存仍能识别原器官；新加的 Behaviour 资源负责保存迁出的参数。演示与检查脚本也已适配新结构。

### 六种执行器怎么调

停止 Play，在 Project 搜索器官名后选 `*Behaviour`，不要选外层同名入口：

- `Organ Id`：种类身份。已有器官不要随意改，否则已有库存的定义 ID 无法匹配。
- `Display Name`：显示名称。
- `Shape = SingleTarget`：单目标直接结算；可调 `Damage` 和 `Status Effect`。
- `Shape = Explosion`：直接范围结算；另有 `Explosion Radius`。
- `Shape = BlackHole`：只吸引，不扣血。调 `Black Hole Radius / Duration / Pull Speed`；Inspector 不展示不适用的伤害或状态字段。
- `Status Effect`：可选状态资源，拖入 `Assets/Data/Statuses/` 中的 Stun、Bleed、Slow。设为 None 只保留直接伤害，不施加状态。

例如，把钢管伤害改大，选 [SteelPipeBehaviour.asset](../Assets/Data/Organs/Actuators/SteelPipeBehaviour.asset) 改 `Damage`。把眩晕持续时间改长，选它引用的 [Stun.asset](../Assets/Data/Statuses/Stun.asset) 改 `Duration`。概率 `Chance Percent` 用 0～100；触发器的 `Probability` 用 0～1，二者单位不同。

同一份状态资源可以被多个器官引用。修改它会影响所有引用者；只想改变某一种器官时，复制该状态资源，再让该器官引用副本。保存后重新进入 Play，运行中的参数快照不会自动随资源热更新。

## 2. 只发动一次，持续效果还能维持吗

**能。持续时间不是靠器官链反复触发来维持的。** 初次发动创建运行对象或目标状态，之后由战场/预览自己的时间推进函数更新，直到结束。

- **眩晕、流血、粘液减速**：目标上的 `StatusEffectRuntime` 保存剩余时间、周期和层数；`BattleOrganCombat.Advance` 持续推进。流血按周期扣血，眩晕到期恢复，粘液减速逐层衰减。它们不要求源器官再次出手。
- **黑洞**：`BlackHoleBehaviour` 保存寿命，由战场推进吸引与到期清理。同一器官实例再次发动会替换自己已有的黑洞；不同实例分别管理。
- **毒雾**：`FogExecution` 创建后停在生成位置，按 `Interval` 对范围内敌人结算，直到 `Lifetime`。
- **章鱼吸盘**：`SuckerExecution` 命中后附着，独立计时并伤害/减速；结束时只移除自己的减速。`Lifetime` 从发射起算，包含飞行时间。
- **环绕、螺旋、追踪、孢子等弹体**：由各自执行实例推进；没有再发动器官链，也会继续飞行或停留到命中/到期。
- **大激光**：第一次发动后开始自己的蓄力计时，到点发射；这与已经取消的玩家攻击充能无关。
- **召唤物**：独立跟随与自然扣血；不靠再次触发维持生命。当前样板没有主动攻击。

主要代码在 [StatusEffectRuntime.cs](../Assets/Scripts/Organs/StatusEffectRuntime.cs)、[BattleOrganCombat.cs](../Assets/Scripts/Systems/BattleOrganCombat.cs)、[ActuatorRuntime.cs](../Assets/Scripts/Organs/ActuatorRuntime.cs)、[EffectExecutions.cs](../Assets/Scripts/Organs/EffectExecutions.cs)。

因此没有给毒雾、弹体等再增加一套重复的“状态文件计时器”。原来钢管等已有的状态文件选项被迁入新的 `DirectActuatorConfig`，并统一开放给单体/爆炸配置使用；黑洞仍只位移。这不表示目前所有弹道配置都支持随意挂 Stun/Bleed/Slow。

持续效果也不是永久效果：自然到期、命中销毁、目标失效等会使其结束；休息清场、失败、重开会清除运行效果。暂停时游戏时间不推进。正常自动循环可能在旧效果结束前又发起一次新攻击，要单独观察寿命，应延长管道节拍或使用自动检查中的单次施加场景。

## 3. 躯干是否装上就改变 Player

**已经做到，躯干不进入器官攻击链。** 装备变化时立即重新计算全部躯干的组合属性，不等待攻击事件。

实际接线是：

```text
库存 LoadoutChanged
  → SpringUpRunDriver 同步装备
  → TorsoEquipmentRuntime.Apply
  → Player 属性修正源 / 管道概率和频率
```

[TorsoEquipmentRuntime.cs](../Assets/Scripts/Systems/TorsoEquipmentRuntime.cs) 修改运行属性：生命上限、伤害倍率、移速、转向、视野、受伤倍率、暴击概率、自动攻击节拍，以及玩家受伤无敌时间和冲锋转向模式。这里是可撤销的属性修正，不是把 PlayerStatsBase 的基础数值永久改写。

前方增伤与吸血是装备后一直有效的结算规则，分别在实际伤害/回血时使用；它们不产生一次“躯干执行”。相机视野由 `SpringUpRunDriver.LateUpdate` 根据装备倍率更新。

卸下时重算剩余躯干，撤销对应修正。生命上限降低时当前血量会受新上限约束；卸下后上限恢复，不免费补满血。多躯干倍率相乘、吸血比例相加并限制范围，详情见 [躯干器官说明](躯干器官实现与验收.md)。

## 4. 触手放到哪里，为什么没有与十杀触发合并

多肢触手已迁入 `Assets/Data/Organs/Triggers/`：

- [MultiTentacle.asset](../Assets/Data/Organs/Triggers/MultiTentacle.asset)：器官入口。
- [MultiTentacleTrigger.asset](../Assets/Data/Organs/Triggers/MultiTentacleTrigger.asset)：具体参数。
- [OrganTriggerConfig.cs](../Assets/Scripts/Organs/OrganTriggerConfig.cs)：与其余触发器共用配置脚本。
- [OrganTriggerRuntime.cs](../Assets/Scripts/Organs/OrganTriggerRuntime.cs)：统一运行规则。

两种击杀配置的玩法不同：

- **多肢触手**：`Condition=Kill`，`Kill Threshold=1`，`Trigger Target=SelfSlots`；每次有效击杀追加发动自身所在管道的全部执行器，包括触手前面的槽位。
- **击杀计数器**：`Condition=Kill`，`Kill Threshold=10`，`Trigger Target=FollowingSlots`；每满十杀追加发动自己后面的执行器。

所以合并了配置和执行代码，没有删掉其中一种玩法。现在可以在 Trigger 资源上调整阈值和触发范围；同链每个触发器实例最多发动一次、链深最多 4 的保护仍有效。

## 5. 静止充能到底怎样运作

它是**“站着不动一段时间，追加发动后面的器官”**，不是玩家攻击必须支付的能量。

例如头部按顺序装：`静止触发 → 直线子弹 → 毒雾`，使用默认参数、没有频率加成：

1. 开始时计数为 0。每静止 1 秒加 1 点。
2. 连续静止约 10 秒，达到 10 点，扣除 10 点，追加发动一次直线子弹与毒雾。
3. 继续静止，再积累到 10 点，再追加一次。若有少量时间步余量，扣除门槛后保留。
4. 若积累到 9 点时移动，立即清零，需要重新积累。

普通自动攻击始终照常运行，不会等这十秒，也不消耗这个计数。触发器只是额外追加一轮。直线子弹仍需要有效目标，毒雾可以无目标生成；若触发器后面没有执行器，会消耗计数但没有攻击产出。

实战看**实际位置是否变化**，不是只看是否按移动键：被推着移动也会清零；顶墙但位置未变可以算静止。实验室用“移动：开/关”模拟这一条件。

在 [StationaryTrigger.asset](../Assets/Data/Organs/Triggers/StationaryTrigger.asset) 调：

- `Charge Rate`：每秒增加多少点，默认 1。
- `Charge Threshold`：达到多少点触发，默认 10。
- `Trigger Target`：默认 FollowingSlots。改 SelfSlots 后会追加整条管道的执行器。

正常静止等待时间约为 `Charge Threshold ÷ (Charge Rate × 躯干触发频率倍率)`。例如频率倍率 1.2 时约 8.33 秒；暂停不增加，换装/换波/死亡重开会重置。每件静止触发器各自计数，彼此不共用能量条。

## 6. 为什么 Critical.asset 和 CriticalTrigger.asset 都留下

**它们是两份配置资源，不是两个脚本，也不是一份无用副本。**

```text
OrganCatalog.asset 的器官清单
  → Critical.asset               类型：OrganConfig
    → CriticalTrigger.asset      类型：OrganTriggerConfig
      → 运行时 OrganDefinition / 每件器官独立的计数
```

`Critical.asset` 是目录、场景和库存适配共用的入口；`CriticalTrigger.asset` 保存暴击触发器的名称、条件、触发范围等行为参数。外层入口让执行器、触发器、躯干可以一起放在同一个 `OrganConfig[]` 中。

直接删除 `Critical.asset` 会破坏目录的引用；删除 `CriticalTrigger.asset` 会让入口缺少行为。当前两者都在用，**均保留**。日常调参选后者。需要改变这种双资源结构，属于目录和场景引用模型的另一轮重构，不能按“删重复文件”处理。

本轮已经移除：

- 空的 `Assets/Data/Organs/Hand/` 及其 `.meta`。
- `OrganConfig.cs` 里旧七器官的 kind、damage、状态、爆炸、黑洞混合字段及专属分支。
- 生产配置中的 `HandOrganKind` 枚举；历史测试用例的同名枚举只留在 Editor 测试工厂。

仍在使用的 HandOrganDemo、HandPipelineLoadout 和 Hand 开头的检查脚本保留，它们仍被演示或回归流程调用；文件名来自早期手部实现，不是弃用标志。移动资源时连同原 `.meta` 一起移动，不让 Unity 生成新的身份。
