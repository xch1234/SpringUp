## 2. 你最后需要做的试玩

### 准备

1. 使用 Unity 6000.5.11f1 打开工程，等待导入、编译完成；若有红色报错，先把完整报错发来。
2. 打开 `Assets/Scenes/SpringUpDemo.unity`，进入 Play。
3. 第一波结束进入休息期，使用 `Tools → SpringUp → 样板` 下的“休息期添加全部执行器 / 全部触发器 / 全部躯干”。建议分批添加、分批试玩；样板未加入正式掉落表。
4. 把要测试的器官装备好，处理超过容量的未装备物品，再进入下一波。不要一次塞满所有器官后才开始判断效果。
5. 若只想快速看效果，打开 `Assets/Scenes/LaboratoryDemo.unity`。预览按钮可模拟受伤、回复、移动和暴击；移动手感与实际相机视野仍需在战场体验。

### 第一轮：操作与界面

- [ ] 移动、索敌、攻击方向符合预期；角色容易控制。
- [ ] 无需按攻击键即可自动攻击；槽位步进与整轮间隔符合预期，休息期停止实战攻击。
- [ ] 左上角装备可读；槽位发动闪光能看清，又不会过于刺眼。
- [ ] 点击“伤害 / 触发记录”能展开收起；能理解伤害来自哪些器官、相同编号表示同一连锁。
- [ ] 战斗期间不能改装，休息期间能装卸、替换；进入下一波后装备生效。
- [ ] 在自己实际使用的分辨率和窗口大小下，按钮、文字及面板没有遮住重要操作。

注意：槽位闪光表示已发动，不保证已经命中；伤害统计按同种器官合计，只计算敌人实际损失的生命，每波重置。

### 第二轮：器官与组合

详细规则已有专门文档，不需要重新抄一遍；请重点标记“效果不符合想象”和“看不出效果”。

- [ ] 分批体验全部 19 种执行器，核对轨迹、范围、墙体阻挡、持续时间与消失条件；给想改的器官记下名称。
- [ ] 试一次“直线子弹 → 计时触发 → 大激光”，检查延迟与蓄力是否容易理解。
- [ ] 试一次“孢子 → 失效触发 → 毒雾”，检查前级结束后追加效果是否符合预期。
- [ ] 试一次“回复触发 → 吸血针”，先让角色损失生命；检查回复和连锁表现。满血时不产生实际回复触发。
- [ ] 在预览中检查受伤、回复、暴击等条件；基础暴击率为 0 时，实战不会自然暴击，可用预览的必定暴击按钮验证。
- [ ] 测试静止充能：实际不移动时积累，移动后清零；它保留独立计数，常规攻击不使用充能。
- [ ] 分别试装 7 种躯干，尤其体验冲锋躯干的转向、视野变化与受伤无敌时间；拆下后检查恢复情况。
- [ ] 至少体验一次两件躯干组合，判断收益与代价是否都能感受到。

当前规则提醒：新触发器不阻止后面的执行器参加普通自动攻击；计时和失效监听最近的前级执行器。躯干卸下后恢复生命上限不会顺便补血。这些是当前规则，不应仅凭现象直接记作程序错误；不喜欢可以记为设计调整。

### 第三轮：完整游戏体验

- [ ] 不依赖加速测试，实际完成一次完整流程，记录每波难度、等待时间和奖励感受。
- [ ] 试一次失败后重开，检查是否有残留效果、计数、装备显示或输入问题。
- [ ] 使用特效较多的组合持续战斗，记录卡顿发生在哪一波、什么组合、多少敌人附近。
- [ ] 记录最强和最弱的组合，说明原因；先描述感受，再决定是否需要具体数值。

目前第七波为计时通关，正式 Boss 尚未完成；第六波暂以 TNT 替代蜘蛛巢。不要把这两项误当作已经交付的最终内容。

## 4. 可以继续交给 AI 的工作

你主要负责提供规则、体验意见和交付范围。以下工作可以直接继续委托，不需要你独自完成：

- 根据反馈修 bug，补复现用例，并回归检查。
- 调整数值、操作方式、提示文字和界面布局。
- 根据确认的器官规则补脚本、配置和效果传递机制。
- 对实际出现卡顿的组合做性能定位；有证据后再优化，不只凭效果数量判断。
- 接入提供的美术、音效和正式数据。
- 核对依赖版本、排查编辑器异常、执行构建并检查构建日志；最终仍需要在目标设备上体验运行。
- 整理验收记录、开发日志及提交说明。
