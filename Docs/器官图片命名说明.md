# 器官图片命名与显示

器官图已按 `Assets/Data/Organs/organs.json` 的 `id` 使用英文小写蛇形命名，例如 `straight_projectile.png`、`compound_eye.png`、`trigger_heal.png`。原图格式保留为 `.png` 或 `.jpg`；每张图片的 `.meta` 与图片一并改名保留，避免丢失 Unity 资源引用。

## 绑定与显示

- JSON 中已有图片的器官，`icon` 字段指向对应 `Assets/Art/Organs/{id}.{ext}`。
- `OrganArtCatalog` 现按 JSON 中的 ID→图片路径建立图标映射；自动刷新入口：**Tools → SpringUp → UI → 刷新器官图片绑定**。
- 自动刷新仅重建图标绑定，不重建 HUD / 背包预制体。刷新后可直接用于战斗装备栏、背包和实验室器官图标。
- 导入的分层 / 多 Sprite 图片改为 **Sprite (2D and UI) → Single**，将整张图显示为一个完整图标；保留透明通道，使用 Point 过滤和无压缩设置，避免像素图发糊或散件只显示一小块。
- 参考图中其余 37 个有素材的器官已建立映射。暂缺图片的 `summon_follower` 保持原图标缺省并显示名称。
- `spider_nest`、`compound_eye`、`treads`、`collection_net` 已绑定图片，但这些旧 JSON 条目原本未接入当前器官玩法目录；本次不会因此自动加入商店或奖励池。

## 修改与新增图片

保留文件名和导入资源不变即可替换图片像素，Unity 引用会自动更新。新增器官时，用 JSON 的 `id` 命名图片，将 JSON 的 `icon` 指向该路径，然后运行 **刷新器官图片绑定**。不要用已有 JSON ID 以外的任意文件名；刷新器会检查文件名、JSON ID、单 Sprite 导入及文件是否存在。

自动验证入口：`SpringUp.EditorChecks.OrganArtChecks.RunBatch`。该检查刷新目录并核对图片名、JSON ID、完整单图 Sprite 和运行时图标绑定；随后还会跑共享休整视野和 HUD Play 检查。
