# 项目配置总览与打包教程

更新：2026-10-20。适用于当前 `Flow/Bootstrap` 正式游戏流程，Unity 版本 **6000.5.11f1**。本文整理日常会修改的场景、资源、脚本和参数；Unity 自动生成的缓存与 `.meta` 文件不逐项展开。

## 1. 从哪里启动，修改如何保存

1. 用 Unity Hub 打开包含 `Assets`、`Packages`、`ProjectSettings` 的工程目录。
2. 打开 `Assets/Scenes/Flow/Bootstrap.unity`，等待编译完成后点击 Play。
3. 在主菜单开始游戏。Battle、Rest 由流程自动加载，不建议单独打开它们后直接 Play 验证完整玩法。
4. 游戏默认 WASD 移动、Shift 疾跑、E 交互、B / Tab 背包、Esc 暂停；可在设置界面改键。
5. 只有在实验室范围内，通过交互键打开实验室，才能装配器官。战斗、商店以及普通背包不能装配。

文件类型与保存方式：

- `.asset`：配置资源。选中后在 Inspector 改参数，保存资源。运行时改 ScriptableObject 也可能保留下来，试玩前记下原值。
- `.unity`：场景及其组件参数。停止 Play 后修改并按 Ctrl+S 保存；Play 中改场景对象通常在退出后还原。
- `.prefab`：可复用对象与 UI。进入 Prefab 模式修改并保存；场景实例的 Override 不一定会写回原 Prefab。
- `.json`：文本配置。保存后重新开局，让配置重新加载。
- `.cs`：算法、行为、工具。修改后等待 Unity 编译；只改字段的代码默认值，不一定改变已有场景或 `.asset` 中保存的值。
- `.png`、动画、音频：美术资源。通过 Inspector 的引用字段接入。移动、改名优先在 Unity Project 窗口操作，保留 `.meta`，避免引用丢失。

推荐流程：停止 Play → 修改目标资源 → 保存 → 从 Bootstrap 开始新局 → 验证对应场景。界面外观与交互矩形支持运行时预览；器官行为等配置在开局生成快照，应重新开局验证。

## 2. 文件与职责导航

- `Assets/Scenes/Flow/Bootstrap.unity`：入口，持有全局 UI、流程、音频和数据引用。
- `Assets/Scenes/Flow/MainMenu.unity`：标题内容场景。
- `Assets/Scenes/Flow/Battle.unity`：战斗世界、玩家、相机和刷怪组件。
- `Assets/Scenes/Flow/Rest.unity`：船只背景、玩家、商店／实验室交互点及木桩。
- `Assets/Scripts/Flow/FlowApplication.cs`：开始游戏、场景切换、窗口、交互授权、调试框、下一波和返回标题。
- `Assets/Scripts/Flow/FlowContent.cs`：场景内战斗接线、休整交互范围、提示及装备 HUD。
- `Assets/Scripts/Flow/GameViewport.cs`：统一 1448×1086 参考画面与 4:3 比例；宽屏左右黑边，窄屏上下黑边。
- `Assets/Scripts/Systems/RunConfiguration.cs`：合并 JSON 与器官资源，生成开局配置快照。
- `Assets/Scripts/Systems/RunController.cs`：波次、库存、交易、骨髓、奖励与装配权限。
- `Assets/Scripts/Organs/`：器官定义、槽位节拍、执行器和触发规则。
- `Assets/Scripts/Systems/BattleOrganCombat.cs`、`BattleActuatorWorld.cs`：器官效果与真实敌人、墙体、伤害的连接。
- `Assets/Scripts/Systems/BattleOrganEffects.cs`：战斗特效、子弹贴图、召唤物显示与血条。
- `Assets/Editor/`：调参菜单、资源生成器和检查工具。包含 Rebuild／装配字样的工具可能重建资源，日常调参数优先使用“编辑／选择配置”入口。
- `Assets/Tests/Editor/`：自动化行为与流程检查；`Logs` 中保存本地检查日志和截图。

`SpringUpDemo`、`Battle_Greybox`、`OrganDemo`、`LaboratoryDemo` 是旧流程、独立演示或验证场景；修改它们不等于修改正式 Flow 游戏。

## 3. 商店与实验室的触发范围

入口：**Tools → SpringUp → 休整区 → 编辑商店与实验室交互范围**。
配置：[RestInteractionSettings.asset](../Assets/Resources/RestInteractionSettings.asset)。

现在使用与船图绑定的两个矩形，覆盖对应柜台贴图及左边少量甲板。玩家中心进入范围后按交互键打开；中间走道不触发任一窗口。判断使用船图的局部坐标，因此船图平移、缩放后范围也跟随。

![商店绿色、实验室蓝色；两块范围之间保留走道](Images/rest-interaction-zones.png)

- `shopArea`：商店矩形，初始 X=0.62、Y=0.55、W=0.28、H=0.23。
- `laboratoryArea`：实验室矩形，初始 X=0.62、Y=0.28、W=0.28、H=0.24。
- `showSceneGizmos`：选中 Rest 场景中挂有 `FlowContent` 的对象，并打开 Scene 窗口 Gizmos 后，显示绿色／蓝色范围线。

坐标以整张船 Sprite 的左下角为 (0,0)，右上角为 (1,1)。X/Y 是矩形左下角，W/H 是宽高。X 增大向右移，Y 增大向上移，W/H 增大则向右／向上扩展。比如想让商店左边再宽一点：把 X 从 0.62 改为 0.60，并把 W 从 0.28 改为 0.30，右边界仍是 0.90。

Inspector 内有船图预览，可边改边看。尽量让两块范围不重叠；若重叠，当前交互选择优先实验室。改完在四条边、四角和中间走道分别走一遍，再测试按 E 打开正确窗口。

船图是 `Assets/Art/Backgrounds/ship.png`。`FlowContent` 的 `shopAnchor`／`laboratoryAnchor` 用于交互标记位置；旧 `interactionRadius` 仅供没有船图或新配置的旧场景回退使用，正式 Rest 范围以本节矩形配置为准。

## 4. 地图尺寸、地砖、视野与画面比例

入口：**Tools → SpringUp → 战斗地图 → 选择地图与视野配置**。
配置：[BattleMapSettings.asset](../Assets/Data/Maps/BattleMapSettings.asset)。

- `columns`、`rows`：地图列数和行数，运行时限制在 3～200。
- `cellSize`：单格世界尺寸，最小 0.5。地图世界宽高 = 列／行数 × 单格尺寸。
- `centerVariants`：中间格随机图片池，每块独立等概率选择。空项跳过；没有有效图片时回退到九宫格第 5 张。
- `borderSprites`：按 1～9 顺序的九宫格边角资源。地砖应为正方形。
- `randomizeOnEntry`：每次进入重新随机；关闭后用 `seed` 复现同一布局。
- `cameraHalfHeight`：基础可见半高。数值越大看得越远、人物越小；战斗与休整共用，并叠加躯干视野倍率。

当前游戏可见区域固定为 4:3：半高 10 时，可见高约 20、宽约 26.67 世界单位，再乘躯干视野倍率。地图物理尺寸与镜头视野是两个独立参数；增大地图不会自动拉远镜头。

`ProjectSettings/ProjectSettings.asset` 保存默认分辨率等 Player Settings；当前默认桌面分辨率为 1448×1086。`GameViewport.cs` 同时约束相机和 UI，单改 Player Settings 的宽高不会解除 4:3。全屏显示器不符合该比例时正常留黑边。

## 5. 战斗／休整 HUD 与调试框

入口：**Tools → SpringUp → 战斗界面 → 编辑 HUD 布局与文字**。
配置：[BattleHudSettings.asset](../Assets/Resources/BattleHudSettings.asset)。

- `wave`、`time`、`health`、`marrow`、`help`：波次、时间、生命、骨髓、操作提示。
- 每项可改 `visible`、锚点 `anchor`、偏移 `offset`、框尺寸 `size`、整体缩放 `scale`、透明度 `opacity`、字号 `fontSize`、文字／背景颜色、对齐、加粗、描边和 `text`。
- 锚点决定偏移基准；X 正数向右，Y 正数向上。`BelowEquipment` 跟随装备栏下边缘。
- `healthBar`：红色填充、空血底色、内边距、是否显示血量数字。
- `equipment`：装备栏开关、底图 Sprite、底板颜色、位置、尺寸、缩放和透明度。
- `images`：额外 HUD 图片列表，可换骨髓图标，并单独设置位置、尺寸、颜色和比例。
- `hideWithWindows`：打开背包／菜单时隐藏 HUD。
- `showDebugPanel`：右下角调试框，默认关闭，战斗和休整共用，运行时立即生效。
- `help.visible`：左下角操作提示，默认关闭。需要显示时在“操作提示”中重新开启。

关闭调试框后，休整区保留独立的“进入下一波”按钮。Esc 暂停、背包和柜台交互仍可使用。

文字占位符：`{wave}` 当前波、`{maxWave}` 总波数、`{time}` 格式化时间、`{seconds}` 秒数、`{health}` 生命、`{maxHealth}` 生命上限、`{marrow}` 骨髓、`{inventoryKey}` 背包按键、`{interaction}` 休整交互提示。保留花括号才能自动替换；可自由修改它们周围的中文。

## 6. 主菜单、设置、胜败结算

入口：**Tools → SpringUp → 主菜单与结算 → 编辑图片、布局和提示**。
配置：[MenuPresentationSettings.asset](../Assets/Resources/MenuPresentationSettings.asset)。

- `cover`：封面 Sprite、位置、尺寸、颜色、透明度、保持比例；`menuScale` 同时缩放封面和点击区。
- `start`、`quit`、`settings`：三个按钮的透明点击区域，中心与尺寸按封面参考坐标设置。`showHitAreas` 可显示调试区域，换图后用它重新对齐。
- `background`、`backgroundFill`、`settlementBacking`：结算背景图、铺满或完整显示、底色。
- `victory`、`defeat`：胜败窗口图片及各自位置、尺寸、透明度；`settlementReferenceSize` 为布局参考尺寸。
- `hintText`、`hintFont`、`hintFontSize`、`hintColor`：返回标题提示文字和字体样式。
- `hintSize`、`hintOffset`、`hintBacking`：提示框尺寸、相对胜败窗口下边缘的偏移和底色。
- `blink`、`blinkPeriod`、`blinkMin`、`blinkMax`：闪烁开关、周期、最低／最高透明度。结算暂停时仍闪烁。
- `inputDelay`：结算防误触时间；默认 0.35 秒。画面内重新点击任意位置直接返回标题，黑边不属于游戏区域。

所需原图位于 `Assets/Art/UI/`，包括 `封面.png`、`背景.png`、`battle-fail.png`、`battle-victory.png`。图片中已经画好的文字不能靠字符串参数改，需要替换图片。以上为默认用途，实际拖入哪张图以当前配置为准。

设置、暂停等窗口 Prefab 在 `Assets/Resources/Menus/`。`Settings.prefab` 目前参考尺寸 1100×1000，标题 44 号，主要文字 30～32 号。要继续改某个文字／按钮，进入 Prefab 模式选择对应 Text／RectTransform 修改。

`MenuSettingsView` 的 `designSize` 要与 Panel 尺寸匹配；`screenHeightFraction` 限制窗口占屏高度。`Assets/Editor/MenuUiBuilder.cs` 保存生成模板，执行 `Rebuild Settings UI` 会重建设置 Prefab；如果做了长期自定义布局，应同步修改模板，避免下次重建覆盖。

游戏里的音量与改键由 `GameSettings.cs` 存入 PlayerPrefs。它们属于玩家本地偏好，不是以上美术配置；“恢复默认”会恢复音量和按键。

## 7. 主角属性、动画与碰撞

主角动画入口：**Tools → SpringUp → 主角 → 编辑主角动画**。
配置：[PlayerAnimationSettings.asset](../Assets/Resources/PlayerAnimationSettings.asset)，原图 `Assets/Art/Characters/1709.png`。

- `rightFrames`／`leftFrames`：左右方向帧，按播放顺序排列。
- `moveFramesPerSecond`、`idleFramesPerSecond`：移动、待机帧率；待机设 0 即停第一帧。
- `sprintAnimationMultiplier`：疾跑动画倍率。
- `height`、`offset`、`initiallyFacingLeft`：显示高度、偏移和初始方向。高度包含整帧透明留白，显示修改不会自动改变碰撞体。

玩家基础属性在 Battle、Rest 两个正式场景的 `World/Player` 组件上：

- `PlayerStatsBase`：`baseMaxHealth` 血量上限、`moveSpeed` 移速、`damageMultiplier` 伤害倍率、`armor` 固定减伤、`healthRegen` 每秒回血、`baseCycleDuration` 器官循环周期等。
- `PlayerRuntime`：受伤无敌基础时长 `baseInvulnerabilityDuration`、部位频率等运行接线。
- `PlayerMotor`：`sprintMultiplier` 疾跑倍率、转向设置和输入引用。
- Collider2D：实际碰撞尺寸与偏移。按身体有效轮廓调小，不能通过缩小子弹／人物图片代替碰撞体调整。

两个场景的玩家不是同一个场景实例；需要一致的基础属性应检查两边。基础视野请用第 4 节的地图配置；不要只改 `PlayerStatsBase.viewRadius` 或运行相机的临时值来调整正式视野。

## 8. 器官数值：JSON 与行为资源的分工

这是最容易改错的部分。正式开局时，`RunConfiguration` 会用行为资源的战斗数值覆盖 JSON 中对应的战斗字段。

- `Assets/Data/Organs/organs.json`：器官 ID、名称、类型、价格、图标路径等库存／经济资料。`shop_price` 调购买价格；图标 `icon` 必须指向有效图片。
- `Assets/Resources/OrganCatalog.asset`：真正接入游戏的器官目录。
- `Assets/Data/Organs/Actuators/*Behaviour.asset`：执行器伤害、射程、速度等实际战斗行为。
- `Assets/Data/Organs/Triggers/*Trigger.asset`：触发条件、概率、延迟和计数阈值。
- `Assets/Data/Organs/Torso/*Torso.asset`：躯干倍率。
- 同目录不带 Behaviour／Trigger／Torso 后缀的资料卡通常通过 `OrganConfig` 引用行为资源，不要把资料卡与行为参数混淆。

例如要提高直线子弹伤害和速度，修改 `Actuators/StraightProjectileBehaviour.asset` 的 `damage`、`speed`，然后重新开局；只改 `organs.json` 的 `damage` 不会覆盖正式战斗快照。

执行器常用参数：

- `damage`：基础伤害；`targetingRange`：索敌距离。
- `speed`：飞行速度，世界单位／秒；`hitRadius`：碰撞半径；`lifetime`：寿命秒数。
- `orbitRadius`、`angularSpeed`：环绕半径与转速；`range`：光束等实际延伸距离。索敌范围与命中范围不一定是同一参数。
- `areaRadius`：范围效果半径；`interval`：持续伤害每跳间隔；`spreadAngle`：散射总角度。
- `explosionDamage`：导弹爆炸伤害；`chargeTime`：蓄能激光蓄力秒数；`driftDuration`：孢子漂浮阶段时长。
- `lifeSteal`：吸血比例；`slowMultiplier`：减速后的速度倍率，越小越慢。
- `health`、`healthDecay`、`followDistance`：召唤物生命、每秒自然扣血、与主角跟随距离。

触发器的 `probability` 填 0～1，例如 0.3 是 30%；`delay` 是延迟秒数，`killThreshold` 是击杀次数。暴击触发、静止蓄能触发已从当前器官目录移除，不应按照旧文档重新加入。

躯干大部分字段是倍率：1 不变、1.2 为增加 20%、0.8 为降低 20%；吸血字段是比例。槽位步进最短 0.25 秒，由 `BodyRuntime.MinimumStepInterval` 保护，不要用极小频率参数绕过节拍限制。

改完运行 **Tools → SpringUp → 检查 → 器官配置完整性**。新增／删除器官还要同步目录、JSON、掉落池与图标引用；仅增加图片不会自动新增器官。

## 9. 子弹、召唤物和器官图标

玩家子弹入口：**Tools → SpringUp → 玩家子弹 → 编辑贴图与动画**。
配置：[ProjectileVisualSettings.asset](../Assets/Resources/ProjectileVisualSettings.asset)。

- `orbit`：环绕弹使用 `Items/子弹.png`；`flying`：直线、螺旋、追踪和三连发使用 `Items/发射子弹.png` 的 5 帧。
- `frames`、`framesPerSecond`：帧序列与帧率；`bodyPixels`：原图金色弹头直径，排除拖尾。
- `sizeMultiplier`：显示直径相对碰撞直径的倍率；`color`：颜色／透明度；`rotate`、`angleOffset`：方向控制；`sortingOrder`：显示层级。
- 原图切片的 Pivot 已对齐弹头，替换素材时要检查 Pivot，避免弹头与真实碰撞位置偏离。改外观不改伤害或碰撞。

召唤物外观配置：[SummonVisualSettings.asset](../Assets/Resources/SummonVisualSettings.asset)。选中资源即可调整 `frames`、`framesPerSecond`、`width`、左右翻转，以及 `showHealthBar`、血条尺寸、偏移、填充色／底色。实际生命、伤害、自然扣血与距离在 `Actuators/SummonBehaviour.asset`，不能靠改血条或动画参数改变。

器官图标位于 `Assets/Art/Organs/`，绑定资源为 `Assets/Resources/OrganArtCatalog.asset`。改 JSON 图片路径或切片名后可运行 **Tools → SpringUp → UI → 刷新器官图片绑定**。Sprite Multiple 图片请引用正确子帧，切勿把整张精灵表当作单帧。

仍使用程序色块／圆环的特效及缺失素材，见 [玩家子弹贴图与器官特效](玩家子弹贴图与器官特效.md)。

## 10. 敌人、波次、奖励、音频

- `Assets/Data/Enemies/*.asset`：各敌人基础属性，常用 `maxHealth`、`moveSpeed`、`attackPower`、`attackCooldown`、`attackRange`、`baseMarrow`。
- 同一资源中 `contactRadius` 管接触判定；`projectileSpeed`、`projectileCount`、`spreadAngleDegrees` 管远程攻击；工厂用 `produceInterval`／`maxAliveProducts`，治疗者用 `healInterval`／`healRadius`／`healPercent`。
- `Assets/Resources/Enemies/*.prefab`：敌人实例、动画与物理 Collider2D。属性配置中的判定半径与 Prefab 的物理碰撞都应按目标玩法检查。
- `Assets/Resources/EnemyWaveMix.asset`：各波次敌人组合权重；权重是相对概率，设 0 表示不选该类型。
- `Assets/Data/Waves/waves.json`：`duration_sec` 波次时长、`marrow_reward` 波末骨髓、`random_drop_pool` 随机器官池、`random_drop_count` 数量、`kill_organ_chance` 击杀掉器官概率。
- `Assets/Data/Waves/SpawnSettings.asset`：前六波刷怪窗口 `firstSixSpawnSeconds`。具体刷怪数量／频率等还应查看 Battle 场景的 `WaveDirector`、`EnemySpawner`；不要把“停止刷怪时间”与“波次结束时间”混为一谈。
- `Assets/Data/Rewards/RewardFlightSettings.asset`：奖励飞行表现，可调骨髓／器官 Sprite、图标大小、等待／飞行／到达时长、弧线高度、曲线和同时显示上限。它不控制实际奖励数额。
- `Assets/Audio/Music`、`Assets/Audio/SFX`：音乐和音效；Bootstrap 中的 `GameAudio` 负责音频引用，玩家设置界面控制音乐／音效音量。

## 11. 导出可游玩的 Windows 版本

### 导出前

1. 在 Unity Hub 确认使用 6000.5.11f1。Windows 构建目标应可用；缺少模块时在该版本的 Add modules 中安装对应 Windows 支持。使用 IL2CPP 还需其构建支持、C++ 工具链及 Windows SDK；首次打包可使用可用的 Mono 后端。
2. 保存资源与场景，退出 Play。Console 中不能有编译错误。
3. 在 HUD 配置中关闭 `showDebugPanel`，确认图片引用完整。从 Bootstrap 测试开始游戏、进入休整、买卖、装配、下一波和胜败返回标题。
4. 建议把输出放到工程根目录下 `Builds/Windows`，不要放进 `Assets`，避免产物被当成新资源导入。

### 使用 Unity 界面导出

1. 打开 **File → Build Profiles**（Unity 6 的构建窗口；旧版本称 Build Settings）。
2. 添加或选择 **Windows** 构建 Profile，目标选 Windows 64 位／x86_64；如有需要点击 Switch Profile，等待平台切换与导入完成。
3. 检查有效 Scene List。若 Profile 开启独立场景列表，以该列表为准；否则使用全局场景列表。勾选并按顺序排列：
   1. `Assets/Scenes/Flow/Bootstrap.unity`，必须位于第 0 个。
   2. `Assets/Scenes/Flow/MainMenu.unity`。
   3. `Assets/Scenes/Flow/Battle.unity`。
   4. `Assets/Scenes/Flow/Rest.unity`。
4. 正式包无需包含旧 Demo 场景，可取消勾选。不要只用“Add Open Scenes”添加 Bootstrap：后面三个场景是运行中加载的，也必须入包。
5. 在 Player Settings 检查 Company Name、Product Name、Version、图标和默认分辨率。当前参考画面为 1448×1086、4:3；宽屏全屏留黑边属于预期行为。
6. 给别人试玩时取消 **Development Build**、Script Debugging、自动连接 Profiler；定位问题时可另导一个开发包。
7. 点击 **Build**，选择 `Builds/Windows`，可将程序命名为 `SpringUp.exe`。或点击 **Build And Run**，构建成功后自动运行。
8. 若失败，查看 Console 的第一个具体错误或构建报告；不能只根据目录中出现了 exe 就判断成功。

### 如何发给别人

将**整个输出目录**一起打包为 ZIP。解压后双击 `SpringUp.exe`，接收者不需要安装 Unity 编辑器。

目录通常包含 `SpringUp.exe`、`SpringUp_Data`、`UnityPlayer.dll`，以及当前后端生成的 `MonoBleedingEdge` 或 `GameAssembly.dll`、崩溃处理程序等。不同后端文件不同，以实际输出为准；不要只发 exe，也不要自行删掉旁边的运行库。改程序文件名时避免破坏它与 Data 目录的对应关系，最稳妥是在构建时确定名字。

发包前，从输出目录直接启动一次，验证主菜单图片、音乐、战斗、休整交互和结算。玩家日志通常位于 `%USERPROFILE%\AppData\LocalLow\<Company Name>\<Product Name>\Player.log`。请以 Player Settings 中的公司名和产品名替换占位符。

### 可选：命令行构建

工程已有 `Assets/Editor/SpringUpBuild.cs`，入口是 `SpringUp.EditorChecks.SpringUpBuild.WindowsBatch`，固定打包上面四个正式场景。

先关闭使用**同一个工程目录**的 Unity 编辑器，或对独立副本执行。下面命令在工程根目录的 PowerShell 中运行：

```powershell
$buildFolder = Join-Path (Get-Location) 'Builds/Windows'
New-Item -ItemType Directory -Path $buildFolder -Force | Out-Null
$env:SPRINGUP_BUILD_OUTPUT = Join-Path $buildFolder 'SpringUp.exe'
& 'C:\Program Files\Unity\Hub\Editor\6000.5.11f1\Editor\Unity.exe' `
  -batchmode -quit -projectPath (Get-Location).Path `
  -executeMethod SpringUp.EditorChecks.SpringUpBuild.WindowsBatch `
  -logFile (Join-Path $buildFolder 'Build.log')
```

若 Unity 安装路径不同，请替换。等待 Unity 完成并检查 `Build.log` 中的 `[SpringUp Build] PASS` 或具体错误。未设置 `SPRINGUP_BUILD_OUTPUT` 时，脚本默认路径为 `Builds/SpringUpDemo/SpringUpDemo.exe`。本次提供的是导出教程与现有构建入口说明，没有生成新的正式发布包。

## 12. 常见问题与快速定位

- **改了伤害没变化**：检查是否只改 JSON；正式战斗参数优先用 Behaviour／Trigger／Torso `.asset`，然后重新开局。
- **新图片不显示**：确认导入类型 Sprite (2D and UI)，引用正确切片，相关显示开关开启，颜色 Alpha／透明度不为 0。
- **图片在碰撞点旁边飘**：检查 Sprite Pivot、透明留白和显示偏移，不要通过修改碰撞伤害位置补偿错误图片中心。
- **商店／实验室开错窗口**：在新范围工具中检查矩形是否重叠，确认角色中心在正确范围内；默认交互键 E 可能已被玩家改键。
- **休整区不能装配**：B / Tab 仍是只读背包，要在实验室矩形内按交互键；打开其他模态窗口时装配权限也会暂停。
- **调参退出 Play 后消失**：场景实例参数应停止 Play 后改并保存；资源参数则检查是否编辑了真正被引用的资产。
- **打包后加载失败**：检查四个 Flow 场景是否都在有效构建列表，Bootstrap 是否第一项，以及资源是否缺失。排查 Player.log。
