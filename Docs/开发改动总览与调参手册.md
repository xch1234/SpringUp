## 2. 我做了哪些功能

### 器官装配与攻击

普通器官不再要求固定装在某个身体部位，可以装入头、手、腿的三条六槽管道；躯干仍使用专用槽。装备限制在库存接口和实验室适配处同时检查，不只是禁用界面按钮。

目前是“每个执行器独立产生攻击 + 条件触发追加攻击”。尚未实现“同一次攻击流经所有器官，逐步叠加形状、伤害和状态”的完整效果传递。

### 19 种执行器

原 Hand 中的拳头、钢管、锈刀、粘液腺、坍缩体、TNT 已迁入 Actuators，使用 DirectActuatorConfig 与各自的 Behaviour.asset。其余已实现直线、环绕、螺旋、激光、追踪、毒雾、吸血针、三发、吸盘、导弹、大激光、孢子和跟随召唤物。

它们共用配置/执行模板，**不是每个器官都对应一个同名 .cs 文件**。直线弹体有独立执行类，其他相似效果共用运行类；每个器官仍有自己的 `.asset` 数值配置。召唤物当前只跟随、有生命和自然扣血，不主动攻击。

### 10 种触发器（9 种条件）

已实现击中概率、前级开始后计时、击杀计数、受伤、回复、前级失效、施加减益概率、暴击和静止充能。全部触发器只发动紧邻后一个执行器，后者跳过自动循环。攻击条件只监听紧邻前一个器官；多肢触手与击杀计数器以 Kill Threshold 区分，默认分别为 1 和 10。

计时和失效监听最近的前级执行器；其他事件按已确认规则监听实际战斗事件。追加攻击保留来源链，同链每个触发器实例最多发动一次、链深最多 4，避免无限循环。静止充能保留独立计数，常规攻击不使用充能。

### 7 种躯干

已实现伤害/概率/频率、生命上限、吸血、正前方增伤、移速与转向、视野和受伤无敌时间的样板组合。装备变动时重新计算倍率，卸下不残留加成；恢复生命上限不会顺便补血。

### 反馈与检查

- 敌人实际受伤时闪白，开火闪黄；受伤反馈优先。
- 左上角只读装备 HUD，触发/出手闪光、可展开伤害与连锁记录。
- 伤害按敌人实际生命损失统计，含持续伤害；同种器官合计，界面显示前六名，每波重置。
- 配置检查菜单、自动化行为/连锁/库存/流程检查，以及模拟混合效果清理压力检查。

## 3. 调数值通常不需要修改脚本

### 三类文件先分清

- `.cs`：规则和算法，例如子弹如何飞、什么时候造成伤害。改变行为时修改。
- `.asset`：一份具体器官的数据，例如伤害 5、速度 8、半径 0.12。日常平衡主要改它。
- `.unity`：场景里放了什么物体、脚本挂在哪里、引用和场景参数是什么。例如移速、相机范围、攻击节拍。

脚本中的 `private float damage = 5f` 是代码默认值；已有 `.asset` 或场景组件通常有自己保存的值。**改代码里的默认值，不等于已经改了现有资源。**

### 标准调参流程

1. 停止 Play，避免把临时运行状态当作永久配置。
2. 在 Project 搜索具体资源名，例如 `StraightProjectileBehaviour`，选中 `.asset`，在 Inspector 修改。
3. 保存资源；场景参数则保存场景。
4. 重新进入 Play。定义在启动/加载时变成快照，不保证运行中改资源立即更新已有装备或已发射效果。
5. 用同一套装备和相近敌人条件比较，先一次只改一类参数。
6. 执行 `Tools → SpringUp → 检查 → 器官配置完整性`，查看 Console。

### 例子：直线子弹伤害提高、飞得更快

选中 [StraightProjectileBehaviour.asset](../Assets/Data/Organs/Actuators/StraightProjectileBehaviour.asset)。把 `Damage` 从当前 5 改成想测试的值，例如 8；`Speed` 从 8 改成 12，然后重新进入 Play。

- `Speed`：世界单位/秒。
- `Hit Radius`：碰撞半径，不是直径。
- `Lifetime`：最多存在几秒；未遇阻挡时大致飞行距离为速度 × 寿命。

旁边的 `StraightProjectile.asset` 是“器官资料卡”，它关联行为配置；日常调弹速不应该改它下面兼容旧器官的字段。

### 例子：毒雾持续更久、伤害跳得更快

选中 [FogBehaviour.asset](../Assets/Data/Organs/Actuators/FogBehaviour.asset)，调整 `Lifetime`、`Interval`、`Area Radius` 和 `Damage`。

`Damage` 是每跳的基础伤害，不是整片雾的总伤害。把间隔变短会增加总伤害；毒雾首次更新即有一跳。`Lifetime` 是持续秒数，`Area Radius` 是覆盖半径。

### 例子：把击中触发改为必定触发

选中 [HitTrigger.asset](../Assets/Data/Organs/Triggers/HitTrigger.asset)，把 `Probability` 改为 `1`；`0.3` 表示 30%，不是填写 30。

选中 `DelayTrigger.asset` 可调整前级开始后的等待秒数；`KillCountTrigger.asset` 的 `Kill Threshold` 是需要多少次击杀；`StationaryTrigger.asset` 的 `Charge Rate` 和 `Charge Threshold` 控制静止积累速率及门槛。

### 例子：调整躯干收益与代价

选中 [OverdriveTorso.asset](../Assets/Data/Organs/Torso/OverdriveTorso.asset)。这里的 `Damage = 1.2` 是伤害倍率，不是伤害值 1.2；`Max Health = 0.6` 是最大生命变为 60%。

躯干大部分字段为倍率：1 不变，1.2 增加 20%，0.8 减少 20%；`Life Steal` 为比例，0.05 即 5%；`Front Half Angle` 为前方扇形的半角，45 表示朝向左右各 45°。多个躯干倍率相乘，吸血比例相加并限制在 100%。

## 4. 场景中哪些组件可以调

### Hierarchy → SpringUp Run

选中场景里的 `SpringUp Run`，不是 Project 中同名脚本文件。

- `SpringUpRunDriver`：管理战斗、休息、下一波及重开，开波重置管道计时并启用自动执行；休息/失败停止管道。已移除充能上限和恢复速度字段。
- 每种执行器在对应 `*Behaviour.asset` 中配置 `Targeting Range`（公共模板字段 `targetingRange`），实战和实验室按该器官的范围索敌，不再受场景旧值 3 限制。拳头 4、锈刀 4.5、钢管 5，远程弹体多数 10～14；全部数值见[全器官名称与用法](全器官名称与用法.md#索敌范围如何调整)。距离按双方中心计算，包含边界。索敌范围独立于爆炸半径、弹体寿命与激光长度；修改后重新进入 Play。
- `BattleOrganCombat`：`Critical Multiplier` 控制暴击伤害倍率，默认 2；是否暴击还取决于玩家属性。
- `OrganPipelineController`：`Step Interval` 是未接属性提供方时的后备值。统一 Demo 会由 Player 属性接管，不应只改这里来调实战攻击间隔。

`TorsoEquipmentRuntime`、`OrganCombatReport` 是运行时创建/绑定的组件；编辑模式下找不到它们并不意味着功能没接入。修改持久参数应改上面的驱动配置或器官资源。

### Hierarchy → Player

- `PlayerStatsBase`：`Base Cooldown` 当前 0.15 秒，控制槽位步进；`Base Cycle Duration` 当前 2 秒，控制实战和预览的整轮节拍，三条管道各自循环。
- `Move Speed`：本次接入 C 场景的 10 世界单位/秒；`Turn Speed`：转向角速度。
- `Base Max Health`：基础生命上限；`Damage Multiplier`：玩家伤害倍率；`Crit Chance`：0～1 的暴击概率。
- `PlayerRuntime`：`Base Invulnerability Duration` 默认 0.3 秒，受伤后的基础无敌时间，躯干可改变它。
- `PlayerMotor`：`Sprint Multiplier` 是疾跑倍率，`Facing Lerp Speed` 是转向速度上限；输入引用为 Move/Sprint。冲锋躯干会让实际移动沿逐步转过来的朝向。

### Hierarchy → Main Camera / BattleSystem

- `Main Camera → Camera → Size`：正交相机半高；本次同步为 10.125。显示宽度还受窗口比例与顶部 HUD 预留视口影响。
- `Main Camera → CameraFollow`：地图中心和半尺寸均从 C 同步；当前中心 (0,0)、半尺寸 (36,36)，开启边界限制。躯干的视野倍率作用于基准 Size。
- `BattleSystem → EnemySpawner`：生成半径、半径随机偏移、距玩家最小距离和地图半宽/半高。本次半宽/半高均为 36。
- `WaveDirector` 在统一入口由流程驱动接管；不要打开它的 `Auto Start` 再让 RunController 同时启动波次。

### 敌人闪色和界面

敌人受伤闪色在对应敌人 Prefab 的 `EnemyAttackFlash` 中调整：`Damage Flash Color` 默认白色，`Damage Flash Duration` 默认 0.16 秒；`Flash Color/Duration` 是敌人自己开火时的闪色。

装备 HUD 的布局和颜色目前由 [RunEquipmentHud.cs](../Assets/Scripts/Systems/RunEquipmentHud.cs) 在运行时创建；原充能面板已删除，战斗记录上移到装备面板下方。槽位闪亮时长 0.35 秒在 [OrganCombatReport.cs](../Assets/Scripts/Systems/OrganCombatReport.cs) 的 `Pulse` 中，目前没有 Inspector 字段。若想频繁调 UI，可以再把这些常量暴露成配置，不用在场景里寻找不存在的静态面板。

## 6. 脚本实际长什么样

下面摘自当前源码。它们已经存在，不需要把示例再复制成第二份脚本。

### 配置：Inspector 上看到的字段来自这里

以下是 `StraightProjectileConfig.cs` 中的配置类主体：

```csharp
[CreateAssetMenu(menuName = "SpringUp/Actuators/Straight Projectile")]
    public sealed class StraightProjectileConfig : OrganActuatorConfig
    {
        [SerializeField, Min(.01f), Tooltip("飞行速度，世界单位/秒；样板初值，可调整。")]
        private float speed = 8f;
        [SerializeField, Min(.01f), Tooltip("子弹碰撞半径，表现尺寸随之变化。")]
        private float hitRadius = .12f;
        [SerializeField, Min(.01f), Tooltip("未命中时最多存在多少秒。")]
        private float lifetime = 2f;

        protected override OrganDefinition CreateDefinition()
        {
            if (Damage <= 0f) throw new ArgumentOutOfRangeException(nameof(Damage));
            return new OrganDefinition(OrganId, DisplayName, OrganType.Actuator, Damage,
                chargeCost: ChargeCost, projectile: new StraightProjectileSettings(speed, hitRadius, lifetime));
        }
    }
```

`[SerializeField]` 让私有字段出现在 Inspector 并保存到资源；`TryCreateDefinition` 会通过模板校验，再产生运行时定义。已有资源优先使用自己保存的值。

### 执行：每次发射创建一个独立状态

以下为 `StraightProjectileExecution.Tick`，真实代码：

```csharp
public void Tick(float deltaTime)
        {
            if (float.IsNaN(deltaTime) || float.IsInfinity(deltaTime) || deltaTime < 0)
                throw new ArgumentOutOfRangeException(nameof(deltaTime));
            if (IsFinished || deltaTime == 0) return;
            float step = Mathf.Min(deltaTime, remaining);
            Vector2 next = Position + Context.Direction * (Context.Projectile.Speed * step);
            if (world.Sweep(Position, next, Context.Projectile.HitRadius, out var hit))
            {
                Position = hit.Position;
                // 先终止再扣血，避免击杀追加/清场回调重入本发子弹。
                EndReason = hit.TargetId == null ? ActuatorEndReason.Blocked : ActuatorEndReason.Hit;
                if (hit.TargetId != null) world.ApplyHit(Context.Hit(hit.TargetId, Position));
                return;
            }
            Position = next; remaining -= step;
            if (remaining <= 0) EndReason = ActuatorEndReason.Expired;
        }
```

它每次更新计算下一位置、检查这段路上是否碰撞，然后决定造成伤害或消失。这里不读 F 键，也不扣充能，所以可以被自动管道或触发器复用，实验室也能使用同一套逻辑。

### 其他执行器如何共用模板

`EffectExecutions.cs` 内的类对应关系：

- `MovingEffectExecution`：环绕、螺旋、追踪、吸血针、导弹、孢子。
- `TripleProjectileExecution`：三颗直线弹体。
- `BeamExecution`：普通激光与蓄力大激光。
- `FogExecution`：静止区域持续伤害。
- `SuckerExecution`：附着、持续伤害与减速。
- `SummonExecution`：跟随、生命和自然扣血。
- `EffectExecutionFactory`：根据配置选择正确的执行类。

配置对象是共享数据；每次执行对象单独保存位置、年龄、剩余寿命等状态。这就是“统一模板”与“每个器官独立参数”同时成立的原因。

## 10. 怎样区分问题与当前规则

- 看不到新器官：样板没有正式掉落，先在休息期使用添加菜单。
- 自动攻击未出手：确认有效敌人在索敌范围内；无目标器官如毒雾、环绕、召唤物有不同规则。
- 紧邻触发器的后一个执行器只在条件成立时发动，跳过自动循环；更后面的普通器官照常执行。
- 触发器放最后没有攻击：后面没有执行器；应调整槽位顺序。
- 100% 暴击触发没有表现：触发器监听暴击事件，不会凭空给角色加暴击率。可先在预览打开必定暴击。
- 调了脚本默认值但效果没变：检查资源/场景保存值，停止 Play 后修改并重新运行。
- 躯干的 Damage 看起来只有 1.2：它是乘数，不是基础伤害。
- 换波后木桩消失：当前木桩也参与统一清场，不是召唤物或永久目标系统。
